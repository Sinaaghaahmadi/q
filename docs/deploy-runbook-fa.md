# راه‌اندازی آسا روی سرور — گام به گام

این نوشته فرض می‌کند شما دانش فنی ندارید. هر گام یک کار است، با دستوری که
عیناً کپی می‌کنید. هیچ‌جا لازم نیست تصمیم فنی بگیرید؛ جایی که انتخابی هست،
نوشته شده کدام را بزنید و چرا.

اگر جایی گیر کردید، خروجی همان مرحله را بفرستید. خروجی‌ها عمداً طوری نوشته
شده‌اند که رمز و کلید در آن‌ها نباشد.

---

## پیش از هر چیز: سه چیزی که لازم است

| چه چیزی        | از کجا                                    | نکته                                           |
| -------------- | ----------------------------------------- | ---------------------------------------------- |
| سرور           | شتابان‌هاست یا هر ارائه‌دهندهٔ داخل ایران | ۴ هسته، ۱۶ گیگ رم، ۱۰۰ گیگ NVMe، اوبونتو ۲۴٫۰۴ |
| دامنه          | همان‌جا                                   | فقط اسم دامنه لازم است                         |
| کلید کاوه‌نگار | پنل کاوه‌نگار → API Key                   | **کلید**، نه رمز پنل                           |

سرور را که خریدید، ارائه‌دهنده یک **آدرس IP** و یک **رمز root** به شما می‌دهد.
رمز را جایی امن نگه دارید و **در هیچ چتی نفرستید** — نه به من، نه به کس دیگر.

---

## گام ۱ — وارد سرور شوید

روی ویندوز برنامهٔ PuTTY یا در ترمینال ویندوز/مک این را بزنید:

```
ssh root@آدرس-آی-پی-سرور
```

اولین بار می‌پرسد «آیا مطمئنید؟» — `yes` بزنید. بعد رمز root را وارد کنید.
هنگام تایپ رمز هیچ چیزی روی صفحه نمی‌آید؛ این طبیعی است.

---

## گام ۲ — ببینید سرور چه می‌تواند بکند

این دستور **هیچ چیزی را تغییر نمی‌دهد**. فقط نگاه می‌کند و گزارش می‌دهد:

```
apt update -qq && apt install -y -qq git curl
git clone --depth 1 -b main https://github.com/Sinaaghaahmadi/q.git /opt/asaex
bash /opt/asaex/deploy/scripts/preflight.sh
```

خروجی‌اش را **کامل کپی کنید و بفرستید**. در آن رمزی نیست. چیزی که برای من
مهم است این است:

- آیا سرور به گیت‌هاب و npm می‌رسد؟
- **کدام مخزن ایمیج جواب می‌دهد؟** داکرهاب به آی‌پی ایران جواب نمی‌دهد و باید
  بدانیم کدام آینهٔ ایرانی کار می‌کند.
- آیا به کاوه‌نگار و به سرویس گواهی SSL می‌رسد؟
- آدرس عمومی سرور چیست؟ (برای تنظیم دامنه لازم است)

---

## گام ۳ — دامنه را به سرور وصل کنید

در پنل شتابان‌هاست، بخش **مدیریت DNS** دامنه، این دو رکورد را بسازید:

| نوع | نام   | مقدار             |
| --- | ----- | ----------------- |
| `A` | `@`   | همان آدرس IP سرور |
| `A` | `www` | همان آدرس IP سرور |

اگر گزینهٔ TTL خواست، `3600` بگذارید.

بعد صبر کنید تا پخش شود — معمولاً چند دقیقه تا نهایتاً چند ساعت. برای اینکه
بفهمید آماده شده، روی سرور این را بزنید:

```
dig +short نام-دامنه-شما
```

اگر آدرس IP سرور را چاپ کرد، آماده است. اگر چیزی چاپ نکرد، هنوز زود است.

> **قبل از آماده شدن دامنه به گام بعد نروید.** گواهی SSL فقط وقتی صادر می‌شود
> که دامنه واقعاً به این سرور اشاره کند.

---

## گام ۴ — نصب

یک دستور:

```
bash /opt/asaex/deploy/scripts/bootstrap.sh
```

این کارها را می‌کند و هر کدام را قبل از انجام اعلام می‌کند:

- بسته‌های پایه و داکر را نصب می‌کند
- **رمزها را می‌سازد** — کلید امضای نشست‌ها، رمز پایگاه داده، رمز پشتیبان‌گیری.
  همه تصادفی و یکتا. من هیچ‌کدام را نمی‌بینم.
- **فایروال را می‌بندد**: فقط سه درگاه ۲۲، ۸۰ و ۴۴۳ باز می‌مانند. پایگاه داده
  از اینترنت اصلاً در دسترس نیست.
- fail2ban را برای جلوگیری از حملهٔ رمز آزمایی روشن می‌کند
- به‌روزرسانی‌های امنیتی را خودکار می‌کند (اما راه‌اندازی مجدد را نه — آن با
  تصمیم شماست)
- پشتیبان‌گیری شبانه، بررسی سلامت هر پنج دقیقه، و تمرین بازیابی ماهانه را
  زمان‌بندی می‌کند

---

## گام ۵ — سه چیز را دستی پر کنید

```
nano /opt/asaex/deploy/.env
```

سه سطر را پیدا کنید و مقدار بدهید:

```
DOMAIN=asaex.ir                 ← نام دامنهٔ شما، بدون https و بدون www
ACME_EMAIL=you@example.com      ← ایمیلی که می‌خوانید (هشدار انقضای گواهی)
KAVENEGAR_API_KEY=...           ← کلید API کاوه‌نگار
```

برای ذخیره: `Ctrl+O` بعد `Enter` بعد `Ctrl+X`.

> **این فایل مهم‌ترین فایل سرور شماست.** یک نسخه از آن را جایی بیرون از سرور
> نگه دارید. اگر گم شود، هیچ نشست و هیچ پشتیبانی قابل بازگشایی نیست.

---

## گام ۶ — بالا آوردن سایت

```
cd /opt/asaex && ./deploy/scripts/deploy.sh
```

چند دقیقه طول می‌کشد (بار اول بیشتر، چون باید برنامه را بسازد). در آخر
می‌نویسد سایت روی چه آدرسی بالا آمده و سه مسیر را از بیرون تست می‌کند.

حالا دامنه را در مرورگر باز کنید. باید سایت را ببینید، با قفل سبز کنار آدرس.

---

## گام ۷ — انتقال اطلاعات فعلی

اطلاعاتی که تا امروز ساخته شده (صرافی‌ها، کاربران، سفارش‌ها) روی سرویس ابری
است و باید منتقل شود. رشتهٔ اتصال را من می‌دهم:

```
cd /opt/asaex
SOURCE_DB_URL='...' ./deploy/scripts/migrate-from-supabase.sh
```

قبل و بعد تعداد رکوردها را می‌شمارد و نشان می‌دهد. **این دو عدد باید یکی
باشند.** اگر نبود، چیزی منتقل نشده و باید بررسی کنیم.

همه باید یک بار دیگر وارد شوند. رمزهایشان کار می‌کند؛ فقط نشست‌های قبلی باطل
می‌شود، چون این سرور با کلید دیگری امضا می‌کند — و این عمدی است.

---

## گام ۸ — کارهای امنیتی که فقط شما می‌توانید بکنید

### الف) کلید SSH بسازید و رمز را ببندید

تا وقتی ورود با رمز باز است، هر کسی می‌تواند رمز حدس بزند. روی **کامپیوتر
خودتان** (نه سرور):

```
ssh-keygen -t ed25519 -C "asaex"
ssh-copy-id root@آدرس-آی-پی
```

بعد روی سرور:

```
bash /opt/asaex/deploy/scripts/harden.sh
```

این بار چون کلید هست، ورود با رمز را می‌بندد. **قبل از بستن ترمینال فعلی، یک
ترمینال دیگر باز کنید و مطمئن شوید با کلید وارد می‌شوید.**

### ب) رمز نمایشی را عوض کنید

رمز `AsaDemo!1404` در مخزن هست و همه می‌توانند ببینندش. تا وقتی عوض نشده،
پنل‌ها با آن باز می‌شوند. این کار **قبل از اعلام عمومی سایت** باید انجام شود.

### پ) یک نسخه از پشتیبان را بیرون از سرور نگه دارید

پشتیبان‌ها هر شب ساعت ۳:۲۰ گرفته و رمزگذاری می‌شوند، ولی روی **همان دیسکی**
هستند که از آن پشتیبان می‌گیرند. یک هارد بیرون از سرور خرابی دیسک را پوشش
می‌دهد:

```
scp root@آدرس-آی-پی:/var/backups/asaex/db-*.enc ./
```

---

## کارهای روزمره

| می‌خواهم                  | دستور                                                     |
| ------------------------- | --------------------------------------------------------- |
| نسخهٔ جدید را بالا بیاورم | `cd /opt/asaex && git pull && ./deploy/scripts/deploy.sh` |
| ببینم چه خبر است          | `cd /opt/asaex/deploy && docker compose ps`               |
| خطاها را ببینم            | `docker compose logs app --tail 50`                       |
| پشتیبان دستی بگیرم        | `./deploy/scripts/backup.sh`                              |
| فهرست پشتیبان‌ها          | `./deploy/scripts/restore.sh --list`                      |
| تمرین بازیابی (بی‌خطر)    | `./deploy/scripts/restore.sh --drill`                     |
| **سایت را فوراً ببندم**   | `cd /opt/asaex/deploy && docker compose stop caddy`       |
| دوباره بازش کنم           | `docker compose start caddy`                              |

### کنسول پایگاه داده

عمداً روی اینترنت نیست. برای باز کردنش، روی **کامپیوتر خودتان**:

```
ssh -L 3001:localhost:3001 root@آدرس-آی-پی
```

و در همان اتصال، روی سرور:

```
cd /opt/asaex/deploy && docker compose --profile console up -d
```

بعد در مرورگر خودتان `http://localhost:3001` را باز کنید. وقتی کارتان تمام شد
`docker compose --profile console down` بزنید.

## اگر سایت بالا نیامد

به ترتیب:

```
cd /opt/asaex/deploy
docker compose ps                 # کدام سرویس بالا نیست؟
docker compose logs app --tail 40
docker compose logs caddy --tail 40
df -h /                           # دیسک پر شده؟
```

خروجی‌ها را بفرستید. در آن‌ها رمز نیست.

اگر همه‌چیز بالاست ولی سایت جواب نمی‌دهد، معمولاً یکی از این دو است:

- **دامنه هنوز به سرور اشاره نمی‌کند** — `dig +short دامنه` را چک کنید.
- **گواهی SSL صادر نشده** — `docker compose logs caddy | grep -i certificate`.
  اگر خطای دسترسی به letsencrypt بود، یعنی سرور به آن نمی‌رسد و باید از
  گواهی خود هاست استفاده کنیم؛ بگویید تا تنظیمش کنم.

---

## چیزی که هر پنج دقیقه خودش بررسی می‌شود

سرور خودش این‌ها را می‌پاید و اگر مشکلی بود **به شما پیامک می‌زند** (اگر
`ALERT_PHONE` را در `.env` پر کرده باشید):

- سایت جواب می‌دهد؟
- سرویسی خاموش یا در حال ری‌استارت پیاپی هست؟
- دیسک بالای ۹۰٪ پر شده؟
- پشتیبان دو روز است گرفته نشده؟

بیشتر از یک پیامک در ساعت برای یک مشکل نمی‌فرستد.

> این بررسی از **داخل خود سرور** است، پس اگر کل سرور خاموش شود نمی‌تواند خبر
> بدهد. برای آن یک سرویس رایگان بیرونی مثل UptimeRobot را روی
> `https://دامنه/api/live` تنظیم کنید — پنج دقیقه کار دارد و همان چیزی است که
> خاموشی کامل را می‌گیرد.
